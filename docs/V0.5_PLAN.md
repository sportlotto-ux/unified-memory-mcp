# v0.5 PLAN — факт-лайфсайкл + temporal-граф + evidence

Источник: аудит покрытия апстримов (LCM 15 → 10, mnemosyne 38 → ядро).
Честные дыры v0.4: temporal-граф и правки/инвалидация фактов + потерянная
canonical-семантика (молчаливый INSERT вместо no-op/supersede).

## 1. Canonical-семантика mem_fact (главное)
Проблема: mnemosyne-слот = одно живое значение на (category, name):
повтор тела — no-op, новое тело — supersede с kept history. Наш mem_fact
всегда INSERT — дубли и противоречия копятся, recall отдаёт рядом.
Решение: `valid_until REAL NULL` + `superseded_by INT DEFAULT 0` на um_facts,
частичный `UNIQUE(owner, category, name) WHERE valid_until IS NULL`.
mem_fact: то же тело — no-op (вернуть существующий id); новое — штамп
старому valid_until + INSERT (история жива, recall — только живые).
Готовность: тесты no-op/supersede/history; дубли невозможны схемой, не словами.

## 2. update + invalidate (дешёвые)
- `mem_forget kind=fact` остаётся жёстким удалением; новое:
  `mem_update(id, body)` = supersede-цепочка (id меняется, replacement фиксируется
  в superseded_by старого — как у саммари, не in-place SQL UPDATE);
  `invalidate` = valid_until=now без замены.
- Закрывает mnemosyne update/invalidate; valid_until-колонка заодно даёт triple_end.
Готовность: цепочки replacement читаются, живые выборки их пропускают.

## 3. Temporal-граф
- um_edges += valid_from/valid_until; `mem_fact(..., valid_until=)` и end_edge
  (режим mem_forget kind=edge + valid_until вместо DELETE? — решить: end по
  умолчанию, delete только с force).
- Graph-arm recall: `as_of` (срез на дату, фильтр valid_from<=as_of<valid_until);
  mem_recent: `kinds` с графом/фактами (сейчас только messages/summaries).
Готовность: as_of возвращает историческое ребро, triple_end прячет из живого.
