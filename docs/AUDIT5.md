## Оценка 5 спорных решений автора

1. `valid_from = created_at` — **ОК**. Нельзя выразить «валидно с даты, отличной от вставки», но для модели достаточно.
2. `as_of` = конец суток, `valid_until` = начало суток — **ОК, но асимметрия** требует явной записи в README (сделано).
3. `as_of` режет все руки — **обязательно** (иначе текст-матч в обход среза). ОК.
4. supersede истекает рёбра — **ОК** (граф без stale); теперь и reopen симметрично возвращает (A3).
5. `mem_fact` = слот по умолчанию — **ОК** как осознанная смена семантики v0.4→v0.5: структурно (partial unique), миграция lossless (dedupe), append-only-спрятать нельзя.

## Отложено (не блокеры, задокументировано)

- Архив выносит только **сообщения**. Истёкшие факты/рёбра и `um_summaries` — TODO.
- `archive.search` написан, но `include_archived` в recall ещё не подключён (архив доступен по id через `mem_expand`). Мёртвый API — подключить или удалить в v0.6.
- Вектора вытесненных/истёкших фактов остаются в `um_vectors` (фильтруются на чтении) — рост, но не корректность.
- `bump_tokens` не уменьшается при архивации — счётчик давления завышает токены после выноса.
- `_dedupe_live_slots` — полный скан `um_facts` на каждом открытии БД (O(n)); при больших сторах — в отдельную миграцию-флаг.
- `mem_doctor(mode=archive)` при большом объёме — до `archive_batch` за вызов; авто-проход ограничен 10 батчами.
- Lazy-maintenance срабатывает на первом вызове тула (read-path side effect). Для stdio это осознанный компромисс; хост может дёргать из cron.

## Что автору зачесть

- Expire-then-insert + `IntegrityError`-backstop — корректно для гонки.
- Sentinel `valid_until=0` + `NOT NULL` против обхода partial-индекса — верно.
- `externalized_ref` переиспользован под указатель архива — удачно (колонка ровно для этого).
- Миграция: dedupe до `CREATE UNIQUE INDEX` — иначе падала бы.
