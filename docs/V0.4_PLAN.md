# v0.4 PLAN — следующая итерация (после сжатия контекста)

Контекст: v0.3.5 закрыл все 4 внешних аудита (54 теста). Ниже — бэклог
в порядке приоритета для публичного продукта. Каждый пункт: что, зачем,

## P0 — безопасность публичного использования

### 0. OpenAI-протокол backend (догфудинг в Hermes!) — ✅ ГОТОВО (12 тестов)
Контекст: в Hermes эмбеддинги НЕ in-process, а через локальный
OpenAI-совместимый сервер `http://127.0.0.1:8127` (model2vec StaticModel,
`potion-multilingual-128M-pruned-int8-ruen`, см.
`.hermes/services/embeddings/server.py`). Mnemosyne ходит туда через
`MNEMOSYNE_EMBEDDING_API_URL`. Наш репо сейчас fastembed-only, а potion НЕТ
в 30 моделях fastembed (проверено `list_supported_models`) → на стенде
автора репо не запустится вообще.
Что: `UM_EMBEDDING_BACKEND=local|openai` (default local), при openai —
`UM_EMBEDDING_BASE_URL` (default `http://127.0.0.1:8127`), model passthrough
(`UM_EMBEDDING_MODEL`), POST `/v1/embeddings` через stdlib urllib (как
`embed_client.py`, ноль новых зависимостей). Dim авто-детект из первого
ответа — dimension-guard уже динамический, подхватит сам (~256?).
Ловушки из комментариев embed-server: model2vec encode() МОЛЧА режет после
512 токенов (у них uncapped, top1 0.281→0.458) — наши чанки/сводки держать
короткими, длинные тела резать до embed с тем же правилом.
Готовность: `UM_EMBEDDING_BACKEND=openai pytest` зелёный против живого
8127; недоступность сервера — EmbedServerError → FTS-only с флагом
`backend_error` в mem_status. ОТКЛОНЕНИЕ от плана: fallback на local НЕ делаем
(план так писал) — смена dim 256→384/768 на живом сторе всё равно упрётся
в dimension-guard; честный FTS-only + громкий флаг правильнее тихого
переключения модели. Факт: pruned potion dim=256, live-тест
`UM_LIVE_OPENAI=1` гоняет настоящий 8127.

### 1. Redaction-гейт (секреты в памяти) — ✅ ГОТОВО (12 тестов + live MCP-check)
Что: `UM_REDACT_PATTERNS_ENABLED` (default **ON** — продукт публичный, LCM держал
off для себя), каталог `api_key,bearer_token,password,private_key` как у LCM.
Резать ДО SQLite/FTS/vectors/summaries, с необратимыми плейсхолдерами.
Готовность: тест кладёт `sk-...`/`Bearer ...` → в БД только плейсхолдер;
`mem_status` показывает флаг; доки предупреждают что redaction forward-only.

### 2. User-isolation (минимум) — ✅ ГОТОВО (7 тестов + live MCP-check)
Что: `session_id` → уже есть; добавить `owner` (tenant) на уровне БД + фильтр
во все запросы. Без этого общий хост читает чужое (задекларировано в README).
Готовность: два owner не видят данные друг друга во всех 10 тулах; миграция
старых БД (owner='' = default).

## P1 — качество recall (закрыть разрыв TOOL_MAP↔код)

### 3. Recency prior + MMR + scope_bias — ✅ ГОТОВО (7 тестов + live MCP-check)
Что: TOOL_MAP обещает, код даёт только RRF. Добавить в `Router`:

дубли DAG не занимают весь топ-N.

## P2 — видимые фичи

### 4. `mem_recent` (temporal) — ✅ ГОТОВО (6 тестов + live MCP-check)
Что: выборки «что было сегодня/на неделе» поверх summaries+messages.
Дешевле `mem_evidence`, ценность для пользователей выше.
Готовность: тул + тесты на границах суток/недель (UTC, как LCM).

### 5. `mem_evidence` (сжатие evidence-семьи LCM) — → v0.5 (не влезло в 0.4)
Что: 1 тул вместо query_state/compute/compile/evidence_pack/retrieve:
режим `cite` (проверка утверждений по exact refs) + `compute` (даты/счёт/суммы).
Готовность: только если останется ресурс; иначе перенести в v0.5.

## P3 — масштаб и гигиена

### 6. sqlite-vec путь — ✅ ГОТОВО (7 тестов + live potion-паритет)
Что: использовать `sqlite-vec` при наличии, brute-force как fallback.
Готовность: флаг в `mem_status`, паритет recall пробами, порог переключения
документирован.

### 7. Hygiene/repair в `mem_doctor` — ✅ ГОТОВО (6 тестов)
Что: `doctor clean` (кандидаты мусора) + `repair` (FTS rebuild) backup-first,
как `/lcm doctor`. Сейчас doctor только читает.
Готовность: dry-run по умолчанию, apply только с флагом.
