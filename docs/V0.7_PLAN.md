## п.4 — guardrails BFS (зафиксированы до кода)

1. **Ветвить, не переписывать.** `_graph_arm` (recall.py:173-197) остаётся дословно как
   есть и обслуживает `hops ∈ {0,1}`. BFS — отдельная функция `_graph_bfs`, вызывается
   ТОЛЬКО при `hops > 1`. «Ноль регрессий» для `hops=1` гарантируется конструкцией
   (старый код не тронут), а не тестом.
2. **Fan-out cap — цифры.** `match_entities(limit=5)` (как сейчас) × `neighbors(limit=100)`.
   Линков с узла — не более **`UM_LINK_FANOUT=20`** на направление. Общий потолок —
   `limit` (остановка при достижении). Без капа dense-узел превращает recall в полный скан.
3. **Скоринг hop≥2 — затухание.** Хиты `_graph_arm` идут `score=1.0`; допрыгнувшие через
   линк без затухания встали бы выше прямых. Спека: `score = 1.0 × decay**(depth-1)`,
   где `decay = UM_GRAPH_DECAY = 0.5`, `depth ≥ 1` — глубина от стартового узла
   (seed = depth 0). Так `depth=1` (один линк от сида) = `1.0`, как старый `_graph_arm`;
   `depth=2` = `0.5`. Максимум по путям при повторном достижении узла.
4. **Просрочка — в обе стороны + session-правило.**
   - «живой линк → истёкший факт» и «истёкший линк → живой факт» — оба случая скрыты
     (проверяется liveness ОБОИХ: ребра/линка И узла-назначения), по тесту на каждый.
   - `session_id` линковой руки действует только при `scope=session` — зеркально
     `_graph_arm` (`session_id if scope=="session" else ""`); у `um_links` колонка
     `session_id` есть.
5. **Мост entity↔content — явно.** Стартовые узлы двух сортов: (а) хиты FTS/вектор-рук
   как `(table,id)`; (б) сматченные сущности как `(um_entities,id)`. Мост факт→сущности —
   через `um_edges.fact_id` (индекс `idx_um_edges_fact` есть), обратно тем же путём.
   `rel`-фильтр: на `um_links` — `rel`, на `um_edges` — `predicate` (при записи
   `lowercased` → фильтр тоже lower). Обязателен `visited-set` на `(table,id)` против
   циклов A→B→A. Узлы-сущности — traversal-only (не эмитятся как хиты).
6. **Запрет self-link** (P4 п.2/п.3) уже в write-path; BFS вдобавок не разворачивает
   линк на самого себя (visited-set).

### Env п.4
- `UM_RECALL_MAX_HOPS=3` — потолок `hops` (выше → отказ/кламп).
- `UM_LINK_FANOUT=20` — линков с узла на направление.
- `UM_GRAPH_DECAY=0.5` — множитель на глубину.

### Тесты п.4
`hops=1` регресс-идентичен v0.6; `hops=2` сквозь линк; `as_of` режет сквозь линк;
«живой линк→истёкший факт» ×; «истёкший линк→живой факт» ×; owner-isolation;
`rel`-фильтр (+ регистр `PREDICATE`); identity `(table,id)` без склейки fact:3 vs message:3;
decay-порядок (прямой hit > hop=2); fanout-cap; цикл A→B→A не зацикливается; потолок
`UM_RECALL_MAX_HOPS`.

## Готовность (критерии)

- Связь message→fact и fact↔fact видна в recall через `hops`; `contradicts` между
  двумя живыми фактами сохраняется и читается обратно.
- `hops=1` не меняет выдачу v0.6 (регресс-тест).
- Истёкшая/чужая связь не течёт в выдачу и в BFS; `as_of` режет **сквозь** линк.
- `mem_batch` с плохим op не пишет НИЧЕГО (rollback); `dry_run` не пишет; caps работают.
- `export` — валидный JSON с `schema_version`, стор не мутируется.

## Env

- `UM_BATCH_MAX_OPS` (дефолт `100`) — потолок ops в `mem_batch`.
- `UM_RECALL_MAX_HOPS` (дефолт `3`) — потолок `hops`.
- `UM_LINK_RELS` **не вводим**: закрытый `CHECK`, расширение — миграцией.

## Тесты (~20-24)

- **schema**: таблица+индексы+partial unique+CHECK (2)
- **write**: базовый линк, дедуп no-op, невалидный `rel`, висячий `src`, owner-mismatch,
  мусорный формат (5)
- **lifecycle**: expire скрывает, reopen, forget hard, owner/чужой (3)
- **BFS**: `hops=1` регресс, `hops=2` сквозь линк, `as_of` сквозь линк, `include_expired`,
  owner-isolation, `rel`-фильтр, identity `(table,id)` без склейки (6)
- **diagnostics**: off по дефолту, on → counts (2)
- **batch**: atomic ok, rollback, dry_run, cap/closed-ops (4)
- **export**: валидный JSON+`schema_version`, read-only (2)
